# 기본 뼈대와 데이터 연결 계획

## 기능 참고 분석

`docs/references.md`에 기록한 LimBooks 로컬 원본을 읽어 다음 흐름을 확인했다. 소스와 에셋을 재사용하지 않고 동작을 새로 구현했다. 참고 저장소는 수정하지 않았다.

| 확인한 파일 | 확인한 동작 | hsrArchive 대응 |
| --- | --- | --- |
| `StoryList.jsx` | 분류별 스토리 목록, 챕터 수 표시 | 개척 임무·시뮬레이션 우주·아카이브 목록 |
| `ChapterList.jsx` | 스토리 선택 후 챕터 목록 | 자료 상세와 챕터 목차 |
| `StoryReaderPage.jsx` | 목록→챕터→본문, 스크롤 복원 | 정적 호스팅용 해시 주소, 읽기 위치 저장 |
| `StoryContent.jsx` | 이전·다음 챕터, 읽기 화면 | 경계에서 이동을 제한하는 챕터 탐색 |
| `useDarkmode.jsx` | 로컬 테마 저장 | 라이트·다크 테마 저장 |
| `NavigationBar.jsx` | 주 메뉴, 모바일 메뉴 | 사이드바와 모바일 탐색 |

추가로 본문 검색, 북마크, 읽기 기록, 글자 크기 조절을 기본 뼈대에 구현했다. 음성 기능과 게임별 특수 콘텐츠는 자료 확보 후 별도로 설계한다. paimooon.github.io를 화면이나 기능 기준으로 사용하지 않았다.

## 사이트 데이터 계약

`src/data/types.ts`의 `ArchiveEntry`는 **사이트 내부 표시용 계약**이다. 실제 추출 도구의 출력 형식으로 확정한 것이 아니다.

- 자료: 고유 ID, 제목, 설명, 분류, 지역, 순서, 언어, 태그
- 출처: 현재 `demo`, 검증된 추출 자료는 `extracted`와 게임 버전·원본 ID
- 챕터: 안정적인 ID와 제목, 순서대로 정렬한 블록
- 블록: 고유 ID, `narration` 또는 `dialogue`, 화자, 텍스트

본문은 React 텍스트 노드로 표시해 문자열을 HTML로 실행하지 않는다. 공식 데이터의 서식 태그, 분기, 선택지, 성별·주인공 이름 치환, 다국어와 음성 ID는 실제 입력을 확인한 뒤 계약을 확장해야 한다. 현재 계약은 그런 요소를 변환하거나 보존한다고 보장하지 않는다.

## 추출·변환을 연결하기 전에

1. 게임 버전과 언어, 원본 입력 파일의 종류를 확인한다.
2. `paimooon.github.io/binary.html`의 지원 입력과 실제 파일의 호환성을 검증한다.
3. 소량의 실제 출력으로 텍스트 ID, 챕터 순서, 화자 참조, 분기와 서식 보존 방식을 확인한다.
4. 검증한 입력 형식 전용 변환기를 추가한다. 미지원 형식은 조용히 누락하지 않고 오류를 반환한다.
5. 원본 출처와 버전을 기록한 사이트 데이터를 생성하고 예시 데이터와 교체한다.

게임 바이너리 추출기는 실행하지 않았으며 현재 게임 입력의 호환성도 검증하지 않았다. 이후 고정된 로컬 한국어 JSON을 검증해 사이트 본문으로 변환하는 경로를 구현했다. 실제 지원 스키마와 연결 규칙은 `docs/content-import.md`를 따른다.

## 후속 확장

아카이브의 7개 분류는 공통 `ArchiveEntry` 계약으로 검색과 북마크에 연결하고, `CodexReader`에서 목록 검색과 항목별 원문 읽기를 제공한다. 공식 영상은 홈 배너 오른쪽에 배치한다. 사용자 제공 분류 아이콘은 `CategoryIcon`에서 공통으로 표시한다.

목록 메타데이터와 챕터 본문을 분리하고 본문을 지연 로딩한다. 전체 검색 자료는 검색 화면에서만 불러온다. `ArchiveEntry` ID와 챕터 ID는 북마크·읽기 기록의 키이므로 데이터 갱신 시 안정적으로 유지해야 한다. 읽기 기록은 마지막 장·대사 페이지·픽셀 스크롤 위치이며 읽음 완료 상태를 뜻하지 않는다.
