2026-10-17 기준. 기능과 검증된 정렬 결과를 main에 반영했다. 최종 사이트 코드 커밋은 `282c836b873c7a8346449994b5e55961016ea039`이며 실제 게시를 확인했다. 기능 도입 뒤 오류 응답 시점부터 대기 시간을 계산하고, 행 삭제와 기존 원문 변경까지 차단하도록 보완했다.

## 동작

- GitHub Actions가 6시간마다 공식 원문 커밋·BWIKI 수정 번호·재시도 일정을 확인한다. 실패 문서의 대기 시간이 지났거나 대조기 해시가 바뀌면 외부 자료 변경 없이도 BWIKI 대상 구간을 다시 검증한다.
- 공식 챕터의 세부 임무를 추가 탐색하고, 조건별 탭·선택지 안의 독립 응답을 경계별로 읽는다. 공식 중국어 ID와 한국어 원문이 명확한 경우만 연결한다. 모호한 문장이나 선택지를 임의로 채우지 않는다.
- 처리한 동일 수정본은 다시 다운로드하거나 재대조하지 않는다. 대조기 개선은 검증된 캐시에서도 다시 실행한다. 재시도 실행의 새 본문 다운로드는 최대 20문서다.
- 수집 실패는 6→12→24→48→72시간 대기와 서버의 Retry-After를 적용한다. 접근 제한·API 오류·연결 실패가 발생하면 추가 BWIKI 요청을 중단한다.
- 실제 배포된 파생 데이터 스냅샷을 다음 실행에 복원한다. 같은 공식 입력에서 저장소가 배포본의 모든 행·원문·검증 근거를 포함하면서 개선을 더 갖는 경우 저장소 개선도 보존한다. 서로 포함되지 않는 결과를 임의로 덮어쓰지 않는다.
- 기존 검증 근거 상실, 행 삭제(미확인 행 포함), 같은 공식 입력에서의 원문·화자·종류·원본 귀속 변경은 게시하지 않는다. 본문·순서·분기의 변경이 있는 재시도만 다국어 자료를 생성하고 테스트·빌드·배포한다. 실행 결과와 실패 사유는 Actions 실행 요약 및 90일 보관 첨부 파일에 남긴다.
