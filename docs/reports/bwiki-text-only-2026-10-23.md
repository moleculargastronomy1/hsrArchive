# BWIKI 순서·공식 텍스트 대조 정책 6

사용자 요청에 따라 BWIKI의 문서 표시 순서를 그대로 사용하고 별도의 게임 실행 순서 판정을 제거했다. 공식 중국어·한국어·화자·종류를 대조한다. 공식 ID가 복수라도 후보 내용이 모두 같으면 텍스트 저장 레코드를 공유해 각 BWIKI 위치에 표시한다. 원문 저장 참조와 실제 출현 ID의 확정은 별개이며, 후보 전체를 `officialCandidateIds`·`contentCandidates`·`idStatus`로 유지한다. 후보의 한국어·중국어·화자가 다르면 자동으로 합치지 않는다. 번역을 생성하지 않는다.

`source-first.py`, `bwiki-placement.py`와 기존 `source-first.mjs` 경로를 확장했다. `update-content.mjs`의 전체 갱신도 기존 게임 순서 복원 단계를 실행하지 않는다. 이전 실행 증거·간선은 보존하며 새 호출·순서를 주장하지 않는다. 기존 증거가 참조하는 원문과 파생 데이터의 해시·보존 계약만 확인한다. 수동·6시간 예약·재시도는 동일한 정책을 사용하고 정책/코드 해시 변경으로 기존 체크포인트를 재대조한다. 새 검증 모듈이나 별도 갱신 시스템은 추가하지 않았다.

BWIKI 선택지의 묶음 ID·개수·위치·앞선 질문을 기록하고 `choiceCoverage`에서 빠진 텍스트를 집계한다. 반복 출현은 각각의 출현 ID를 유지하고, 응답은 BWIKI에 명시된 구조만 연결한다. 대조 TXT에도 ID 후보가 복수임을 구분한다. 일반 화면에는 내부 검증 문구를 추가하지 않는다.

## 격리 확인

- 전체 개척임무·개척 후문 36개 읽기 항목의 기존 파생 데이터를 재사용해 대조했다.
- 제8막은 원문 저장 행 2,918 → 2,928개, BWIKI 출현 2,792 → 2,887개, 순서 미확인 원문 180 → 154개였다.
- 같은 질문의 ID 후보 `146793515 / 146793524`와 같은 선택지의 후보 `146793519 / 146793528`은 중국어·한국어·화자가 동일했다. 텍스트 저장 참조를 공유하면서 각 후보와 미확정 상태를 보존했다. 두 질문이 각각 올바른 선택지 묶음 앞에 표시되고 두 묶음의 선택지는 각각 5개임을 데이터와 실제 화면에서 확인했다.
- 기존 원문·ID·귀속·출현 위치·선택지/실행 연결·URL의 손실 및 충돌 검사는 모두 0건이었다.
- 회귀 테스트 134개, TypeScript 검사와 정적 빌드가 통과했다. 추가로 후보 한국어/화자 불일치 차단, 기존 선택지 저장 형식 호환, 별도 실행 순서 알고리즘을 호출하지 않는 시험을 포함했다.
