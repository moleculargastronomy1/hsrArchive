# 자동 연동 안정화 및 최소 리팩터링

기준 소스는 `59fabea`이며, 마지막 성공 사이트 소스는 `36c363b9c443ba31fb466e8dfef3e33a4ecea95d`다. 기존 공식 원문·연결 증거·읽기 주소·UI를 유지하면서 점검한 세 부분만 수정했다. 새 대사를 수집하거나 새 매칭 기준을 추가하지 않았다.

## 변경과 단계별 검사

| 단계 | 변경 | 검사 |
| --- | --- | --- |
| 1 | 관측 캐시와 성공 배포를 구분. 게시 실패한 영상·목록 변경은 계속 감지 | 감시 테스트 9개 통과 |
| 2 | BWIKI·유튜브 코드 해시 분리. 공통 안전 규칙은 양쪽에 적용. 미게시 개선은 전체 경로로 복구 | 관련 테스트 29개 통과 |
| 3 | 유튜브 집계·저장·검색 동기화를 별도 모듈로 이동, 중복 집계 제거 | 관련 테스트 31개 통과, 이전/이후 실자료 비교 통과 |

단계별 테스트는 중복되는 항목을 포함한다. 최종 전체 Node 테스트는 86개, Python 테스트는 53개이며 모두 통과했다. Node 테스트에 Python 검증기 호출도 있으므로 두 수를 합산하지 않는다. 최종 데이터 계약 검사와 사이트 빌드도 통과했다.

### 배포 실패 재현

실제 예약 실행 명령을 가짜 네트워크 응답으로 실행했다. 새 공식 영상, 동일한 대사 digest, 진행된 감시 캐시, 실패한 게시의 조합에서 다시 전체 갱신이 선택된다. 이전 형식 캐시와 새 형식의 게시 대기 캐시를 모두 검사했다. 실제 게시가 성공해 공개 메타데이터가 새 상태가 된 경우에는 다시 처리하지 않는다.

개선 없는 재시도는 같은 기준 배포본에서 BWIKI 관측 수정 번호만 재사용한다. 기준 배포본이 달라지거나 게시가 필요한 결과라면 이 관측본을 승인하지 않는다. 실제 배포를 고의로 실패시키지는 않았다.

### 독립 변경 감지

임시 복사본에서 유튜브 코드만 수정했을 때 BWIKI 해시는 동일하고 영상 해시만 바뀌는지 확인했다. BWIKI 코드만 수정했을 때는 반대다. 공통 통합 규칙을 수정하면 둘 다 바뀐다. 유튜브만 실행한 결과가 BWIKI의 미실행 버전을 완료 처리하지 않고, 영상의 최신 대기 기록을 덮어쓰지 않는지도 확인했다.

## 데이터 회귀 비교

- 저장소 전체 본문 2,454개, 61,111행, 선택지 4,415개와 검색·다국어·메타데이터 등 9,833파일을 변경 전후 비교했다. 바이트와 ID·본문·선택지·순서·검증 상태 해시가 모두 동일하다.
- 이미 확인한 시뮬레이션 화면 경로가 포함된 고정 자료를 이전·이후 유튜브 실행기에 각각 적용했다. 개척 임무·시뮬레이션 327개 본문과 전체 검색 자료 61,111행의 출력 바이트가 동일하다. 장별 집계·제목 연결·증거·충돌·대기 결과도 동일하다.
- 이 전후 실행은 같은 목록·증거와 조회 대기 상태를 사용해 외부 요청 없이 비교했다. 실행 시각과 새 영상 알고리즘 표기만 의도적으로 다르다.
- 원본 입력, React·CSS, 기존 파생 본문은 수정하지 않았다. 자동 실행은 기존 GitHub Actions와 스크립트를 사용하며 AI API를 호출하지 않는다.

## 실제 배포 및 예약 모드 확인

[자동 배포 39060034756](https://github.com/moleculargastronomy1/hsrArchive/actions/runs/39060034756)의 데이터 검사·테스트·빌드·Pages 게시가 성공했다. 2026-10-18 03:56 KST에 공개 사이트 소스 `f4c0dae072b37f0801898730c6509bb9bb4d43f0`를 확인했다. 공개 진행 기록과 영상 상세의 `videoAlgorithm`이 일치하고 BWIKI `algorithm`과 별도로 기록된다. 기존 원문·검증·간선 손실과 확인된 순서 역전은 0이다. 시뮬레이션 화면 확인 3행·순서 간선 2개와 프롤로그 자막 일치 87개·충돌 보류 상태를 보존했다.

이후 [예약 모드 시험 39060263180](https://github.com/moleculargastronomy1/hsrArchive/actions/runs/39060263180)을 `detect_changes=true`로 실행했다. 원문·재생목록·공식 영상이 같고 BWIKI가 대기 중인 조건에서 실제로 `mode=retry`, `retryBwiki=false`, `retryVideo=true`가 선택되었다. 영상 2개만 조회하고 BWIKI 본문 다운로드는 0건이었다. 새 연결 개선은 0이므로 빌드·업로드·배포를 생략해 기존 게시본을 유지했다. 남은 기한 도래 영상 48개와 순서 미확인 15,009행을 기록했다. 조회 실패를 검증 성공으로 세지 않았다.

위 성공 실행의 실제 첨부 기록과 공개 게시 자료를 검사했다. 배포 실패 복구는 모의 응답으로 재현했고, 독립 재시도·개선 없는 실행의 게시 생략은 실제 GitHub Actions에서도 확인했다.
