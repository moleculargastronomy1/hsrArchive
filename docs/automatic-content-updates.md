# 원문 자동 갱신

최신 릴리스 커밋에서 언어별 파일을 조회·병합하고 검증한 뒤 아카이브의 한국어 원문을 갱신한다.

## 실행 시점

기존 `.github/workflows/deploy-pages.yml`의 main push, 수동 실행, 6시간 cron에 원문 갱신 단계를 연결했다. 매 방문자에게 전체 원본을 다운로드시키지 않고 배포 과정에서 검증·변환한 자료를 제공한다. GitHub 예약 실행은 대기 상황에 따라 지연될 수 있다.

## 처리 과정

1. GitHub REST API의 `commits/main`에서 `DimbreathBot/TurnBasedGameData` 릴리스 커밋과 버전 문자열을 읽는다.
2. 그 커밋으로 `TextMap` 디렉터리와 ExcelOutput Git tree를 조회한다. Contents API의 1,000개 파일 제한 때문에 전체 테이블 목록은 Git Trees API로 조회한다.
3. `TextMapKR.json` 또는 연속된 `TextMapKR_0.json` 등의 한국어 조각과 영어(`EN`)·중국어 간체(`CHS`)·일본어(`JP`) TextMap, `NounAtlas`, `NounAtlasChangeInfo`, `TalkSentenceConfig`, `MissionChapterConfig`를 받는다. 각 언어의 전체·분할 형식을 검증하고 서로 다른 커밋의 파일을 섞지 않는다.
4. 파일마다 Git blob SHA-1을 검증하고 내용 기반 캐시에 보관한다. Python 정수로 JSON을 파싱하여 64비트 해시 정밀도를 유지한다.
5. 임시 출력에서 자료실 세 분류를 다시 생성하고, 기존 행을 정확한 TalkSentence ID 또는 보존된 텍스트 해시로 갱신한다. 기존 임무·장면·선택지 역할과 행 ID는 보존한다. 연결되지 않은 문장은 기존 본문을 유지한다.
6. 원본 실행 구조 복원 후 `bwiki-dialogue.py --discover` → `import-bwiki-chapters.py --discover` → `fetch-bwiki.mjs` → 두 대조기의 반영 단계로 항상 BWIKI 순서·분기를 대조한다. 정확한 중국어 원문·화자·대사 ID와 공식 한국어가 일치하는 구간만 적용한다. 소개문만 있는 신규 장도 공식 임무 소속과 BWIKI 시리즈가 일치하면 부분 본문으로 확장한다. 모호한 구간은 기존 자료를 유지하며, 외부 조회 실패 시 이전 파생 연결을 현재 원문과 다시 검증한다. BWIKI 접근 제한을 우회하지 않고 요청을 중단한다. 기준과 재사용 조건은 [BWIKI 순서·분기 대조](content-import.md#bwiki-순서분기-대조)를 따른다.
7. `verify-video-order.mjs`가 등록된 한국어 재생목록을 갱신하고 미확인 장의 공개 자막을 보조 대조한다. 매번 최대 두 영상을 확인하며, 최근 24시간에 확인한 영상은 건너뛰어 다른 미확인 영상도 순환한다. GitHub Actions 캐시에 파생 확인 기록만 보존하고 현재 원문 해시를 다시 검증한다. 읽을 수 없는 자막과 충돌은 미확인으로 기록한다. 제목·영상 목록만으로 순서를 확인했다고 처리하지 않는다.
8. `import-localizations.py`가 동일한 해시의 한국어가 표시 원문과 일치하는 행만 영문·중문·일문으로 연결한다. 모든 payload·메타데이터·행 ID·행 개수를 검증한 뒤 생성 결과와 전체 검색 자료·언어별 비교 파일을 반영한다. 테스트와 빌드까지 통과하면 Pages에 배포한다. 원본 다운로드·변환·테스트 중 실패가 있으면 새 배포가 실행되지 않는다.

다운로드 URL은 API가 알려 준 파일의 경로와 고정 커밋으로 구성한다. `GITHUB_TOKEN`은 GitHub Actions의 공개 자료 조회에만 사용하며 파일·로그·배포물에 저장하지 않는다. 원본 JSON과 캐시는 `.cache/upstream-content`에만 둔다. 자동 실행은 저장소에 커밋하거나 쓰기 권한을 확대하지 않는다.

## 갱신 범위와 한계

- 에이언즈·고유 명사·파벌: 최신 NounAtlas의 항목·정렬·본문·갱신 기록을 반영한다. 기존 기록이 갑자기 사라지면 검증을 중단해 저장된 읽기 주소를 임의로 지우지 않는다.
- 기존 개척 임무·시뮬레이션 우주 대사: 정확히 연결되는 대사 ID의 한국어 본문과 화자 이름을 갱신한다. 같은 릴리스의 실행 구조와 실제 선택지 신호를 대조해 확인된 장면 연결만 복원하며, 미확인 구간은 원래 순서를 유지한다. 원래 배열·행 ID·본문을 보존하고 입력 해시와 확인 대상은 `public/dialogue-flow-provenance.json`에 기록한다. 자세한 기준은 [확인된 장면 연결 복원](content-import.md#확인된-장면-연결-복원)을 따른다.
- 다른 설정 기록·기물: 최초 변환 때 보존한 문자열 해시가 최신 한국어 맵에 있으면 갱신한다. 해시 자체가 바뀌거나 연결이 없으면 기존 기록을 유지한다.
- 신규 개척 임무: 한국어 챕터·소속 임무 제목을 검색하고 `MissionChapterConfig`의 챕터 ID → `MainMission.ChapterID` → 정확한 임무 디렉터리의 JSON 구조 → `TalkSentenceConfig` → TextMap을 연결한다. 정규 장·서막·번호가 있는 후문·종말 표기를 지원한다. 기존 본문과 주소는 유지하며 신규 장 및 자동 연결한 장을 재검사한다. 새 지역의 사이트 분류가 없으면 은하의 기록 아래 새 장으로 등록한다.
- 제7막: 실행 구조는 아직 없지만 BWIKI의 해당 시리즈 문서에서 공식 대사 ID·자막 해시가 유일하게 연결되는 부분 본문을 자동 수록한다. 소속 임무 모두의 구조·대사 참조가 제공되고 지원 스키마로 검증되면 같은 주소에서 실행 구조 기반 연결을 보완한다. 텍스트 존재나 숫자 접두사로 귀속을 추정하지 않는다.

`public/content-update.json`은 적용 커밋·릴리스 버전·확인 시각·입력 해시·정확히 연결한 행 수·기존 원문을 유지한 행 수를 공개한다. 각 payload는 원래 구조 출처를 보존하며 `textReferenceCommit`과 `retainedTextRowIds`를 통해 갱신 범위를 구분한다. `docs/content-provenance.json`은 최초 변환 자료의 고정 감사 기록이며 자동 갱신 기록은 별도다. 사이트 안내에서 버전과 확인 시각을 표시한다.

메인 공지사항의 날짜는 `아카이브 업데이트 : YYYY.MM.DD`로 표시한다. 소스 수정 사항을 배포할 때 날짜를 자동 생성한다. `pnpm build`가 `scripts/update-site-status.mjs`를 실행하여 현재 Git 커밋과 커밋 시각을 `public/site-update.json`에 기록한다. 화면은 한국 시간 날짜를 표시한다. 새 수정 커밋이 배포되면 날짜가 바뀌며, 같은 소스의 예약 재빌드나 자료 재확인만으로는 날짜가 바뀌지 않는다. 게임 출시일이나 원본 자료의 확인 시각과 구분한다.

`latestTrailblaze`는 검증된 `MissionChapterConfig`와 같은 커밋의 한국어 TextMap에서 매번 생성한다. 번호가 있는 정규 개척 임무 중 가장 뒤의 장·막을 선택하고 후문·종말·이벤트는 제외한다. 원본의 `제5막•제7장` 표기는 사이트의 장·막 체계에 맞춰 `5장 7막`으로 표시한다. 새 버전에 새 정규 장이 있으면 제목과 번호도 자동으로 바뀐다. 이 공지는 릴리스 자료의 최신 임무를 안내하며, 해당 임무의 대사 본문 수록 여부와는 별개다.

화면은 빌드에 포함된 기록을 즉시 표시하고, 열 때마다 공개 갱신 파일을 캐시 재검증하여 읽는다. 파일 조회가 실패하거나 형식이 잘못되면 빌드에 포함된 기록을 유지한다.

## 로컬 실행

Node.js 22.13 이상, Python 3.10 이상이 필요하다. Python 경로는 `HSR_PYTHON`으로 지정할 수 있다.

```sh
pnpm update:content
pnpm test
pnpm build
```

GitHub Actions는 같은 실행을 두 단계로 나눠 커밋별 원본 캐시를 복원한다.

```sh
node scripts/update-content.mjs --plan
node scripts/update-content.mjs --apply
```

`--apply`는 바로 앞에서 확인한 계획을 사용한다. 확인 시각도 계획의 시각으로 기록한다. 수동 고정 자료 재생성 스크립트를 실행한 경우에는 자동 갱신을 다시 실행해 최신 기록과 검색 자료를 맞춘다.

신규 임무 연결만 특정 제목으로 좁혀 실행하려면 `node scripts/update-content.mjs --title "달 뜨기 전, 괴수와 춤을"`을 사용한다. 공백·서식·가운뎃점 차이를 정규화해 챕터 또는 소속 임무 제목을 검색하며, 기존 원문의 갱신은 그대로 실행한다. 예약 실행은 제목 제한 없이 모든 지원 챕터를 확인한다.

`src/data/trailblaze.json`은 자동 발견한 장과 공식 챕터 ID 연결을 보존한다. `public/trailblaze-provenance.json`에 입력 커밋·Git blob·SHA-256, 기존 본문 유지(`preserved`), 구조 연결 완료(`structured`), 연결 대기(`pending`)와 누락 사유를 기록한다. 이 기록은 최초 고정 변환 감사 기록과 구분한다.

현재 지원하는 본문 구조는 `Story/Mission/{정확한 임무 ID}`와 `Config/Level/Mission/{정확한 임무 ID}`의 JSON이다. `SimpleTalkInfo`, `OptionTalkInfo`, 단순 대화 작업과 선택지 목록의 명시적 `TalkSentenceID`를 연결한다. 타임라인은 같은 임무 디렉터리에 참조된 JSON이 있을 때만 읽으며, 바이너리 타임라인·연결되지 않은 Performance·미지원 대사 스키마·한국어 누락·소속 임무 구조 누락이 있으면 소개문 또는 이전 검증 본문을 유지한다. 현재 게임의 전체 장면 수록을 보장하지 않는다.

최초 로컬 검증에서는 `OSPRODWin4.6.0_D16728363_A16704710_L16700845`, 커밋 `312b4597691e0a29cf9828a15b592757dba86949`로 58,598개 행 중 58,274개를 정확히 연결했고, 447개 행의 문구·화자를 갱신했다. 324개 행은 기존 본문을 유지했다. 같은 원본으로 다시 실행하면 문구 변경 수는 0이며 중복 행을 추가하지 않는다.

BWIKI 대조 뒤에 소개문만 있던 장의 부분 본문 연결과 한국어 플레이 영상 보조 대조를 실행한다. 자세한 기준은 [소개문에서 BWIKI 본문으로 확장](content-import.md#소개문에서-bwiki-본문으로-확장)과 [한국어 플레이 영상 보조 대조](content-import.md#한국어-플레이-영상-보조-대조)를 따른다. 기존 GitHub Actions의 6시간 주기와 main 배포에서 매번 실행하므로 수동 갱신 명령이 필요하지 않다. 다만 영상의 공개 자막을 읽을 수 없으면 그 구간은 미확인으로 남기며, 확인된 BWIKI 본문의 갱신은 계속한다.
