# BWIKI 전체 수록과 순서 검증 조건

현재 운영은 사용자 지정 정책 6을 우선한다. BWIKI 문서의 표시 순서를 그대로 사용하고 별도의 게임 실행 순서 판정을 하지 않는다. 공식 중국어·한국어·화자·종류가 일치하는 텍스트를 연결한다. 공식 ID 후보가 여러 개라도 내용이 모두 동일하면 텍스트 저장 참조를 공유하고 후보 전체와 ID 미확정 상태를 기록한다. 기존 ID·원문·북마크·검증된 연결은 보존한다. 아래의 실행 순서 및 ID 유일성 관련 과거 실험 조건은 현재 표시를 차단하는 조건이 아니며, 상세 운영 기준은 `editorial/source-first-policy.json`과 `docs/content-import.md`를 따른다.

제4장 제8막 「어제의 내일이 되어」의 2026-10-21 실험을 출발점으로 한 전체 임무 검증 계약이다. `source-first.py` / `source-first.mjs`는 등록된 개척임무·개척 후문의 전체 출현 위치 조사, 전역 후보 검색, 공식 임무 귀속 검사, 체크포인트와 안전한 부분 추가를 구현한다. 전체 수록을 모든 분기의 검증 완료와 같은 상태로 처리하지 않는다. 아래 과거 실험 수치는 당시 기준이며 현재 자동 확정 건수가 아니다.

## 수집 대상과 완료의 분모

기존 사이트 행을 출발점으로 BWIKI에서 같은 문장을 찾는 방식만으로는 누락된 본문을 발견할 수 없다. 먼저 공식 장과 연결한 BWIKI 문서의 **모든 대사·선택지·내레이션·조건 탭·접힌 추가 대화**를 출현 위치별로 목록화한다. 미지원 문법·조회 실패·문서 없음도 목록에 남긴다. 이런 항목을 제외해 완료율을 높이지 않는다.

출현 위치의 키는 공식 장 ID·위키 문서 ID·수정 번호·구조 경로·종류·원문 해시로 구성한다. 같은 문장이 두 분기에 등장하면 두 출현 위치를 유지한다. 한국어 원문 행 ID는 원문 식별자이며 출현 위치와 일대일일 필요가 없다. 기존 행 ID·북마크·원래 귀속은 보존한다.

다음 세 집계를 나란히 제공한다.

| 집계                | 분모                               | 완료 조건                                                                               |
| ------------------- | ---------------------------------- | --------------------------------------------------------------------------------------- |
| 원문 수록           | 수집한 BWIKI 출현 위치             | 공식 한국어 행으로 연결했거나 명시적인 제외 사유가 있음. 제외는 연결 성공으로 세지 않음 |
| 국소 순서           | 같은 장면·같은 조건 안의 연결 후보 | 직접 관측한 위키 순서/분기 또는 공식 실행 구조로 연결됨                                 |
| 분기·임무 전체 경로 | 시작·종료·선택·합류·임무 전환      | 모든 경계와 경로가 확인되고 충돌·미조회·미해석 항목이 없음                              |

세 번째 조건이 충족되기 전에는 `전체 검증 완료`를 표시하지 않는다. BWIKI에 수록하지 않은 게임 분기는 별도의 범위이며, BWIKI 전체 수록으로 게임 전체 분기를 완료했다고 표현하지 않는다.

## 한국어 원문 연결

BWIKI 문서의 임무 유형·공식 임무명·시리즈가 공식 챕터/임무 카탈로그와 맞아야 한다. 같은 제목의 세부 임무가 여러 개면 문서 단위 귀속을 유지하고 임의의 세부 임무 ID를 선택하지 않는다.

원문 연결은 다음 순서로 판정한다.

1. **현재 장의 정확 일치:** 중국어 본문·화자·종류가 유일하고, 정확한 대사 ID의 공식 한국어가 일치한다.
2. **누락된 공식 대사 추가:** 전역 TalkSentenceConfig에서 중국어·화자·종류가 유일하게 대응하고 같은 커밋의 공식 한국어가 있으면, 장·임무·수정본을 확인한 BWIKI 출현 위치에 수록한다. 공식 실행 파일의 호출 관계는 수록 필수 조건이 아니다. 문서가 여러 공식 임무에 대응하면 기존 BWIKI 문서 그룹 ID를 표시 귀속으로 쓰고 공식 임무 후보는 별도로 보존한다. BWIKI 문서 귀속 자체가 불명확하거나 공식 대사 ID 후보가 여러 개면 미확정으로 남긴다. 숫자 접두사나 파일 배열 위치로 귀속을 추정하지 않는다. 같은 공식 ID는 원문 행을 공유하고 출현 위치만 나눈다.
3. **공식 자막/내레이션:** 위키에서 자막·내레이션 역할이 명시되고 중국어 TextMap 해시가 유일하며 같은 해시의 한국어가 있을 때 연결한다. 일반 장면 지시문을 게임 원문으로 만들지 않는다.
4. **번역 내용 대조:** BWIKI 발화를 한국어로 번역하고 기존 공식 한국어 후보와 비교한다. 발화의 행동·대상·부정·수량·고유명사·시제·조건·화자 역할이 보존되고, 같은 공식 장에서 후보가 하나일 때만 검토 기록으로 채택한다. 비슷한 주제나 주변 이야기의 맥락, 자동 유사도 점수만으로는 채택하지 않는다. 편집자 부연은 실제 발화와 구분한다.
5. **복수 후보:** 같은 말을 하는 서로 다른 공식 ID가 남으면 후보를 모두 기록한다. 공식 분기 구조·명시된 조건·직접 확인한 영상 경로로 하나가 되기 전에는 임의로 선택하지 않는다. 번역해도 같은 두 ID는 번역으로 구분할 수 없다.

번역문 자체를 공식 한국어 원문 대신 수록하지 않는다. 번역 검토로 연결한 행에는 `번역 내용 대조`를 표시한다. 검토 기록에는 위키 원문과 수정 번호·문서 해시, 공식 ID·중국어·화자·한국어 해시, 번역문·판정 이유를 남긴다. 입력 변경 시 재검사하며 이전 판단을 다른 문장에 일반화하지 않는다.

새로운 번역 의미 대응은 자동 승인하지 않는다. 기존 `bwiki-translation-matches.json` 검토만 해당 수정본·문서 해시·공식 중국어/화자/한국어 해시가 모두 유지될 때 재사용한다. 사용자 제공 TXT는 독립 평가 전용으로 유지하며 연결·순서·귀속·자동 수록의 입력에서 제외한다. 자막에 없는 선택지·무더빙·화면 전용 구간을 누락 오류로 판정하지 않는다.

## 순서와 응답 연결

텍스트가 매칭됐다는 사실만으로 해당 행 앞뒤의 순서를 확정하지 않는다. 순서는 원문 행 배열을 임의로 바꾸는 대신, 출현 위치 사이의 **범위가 명시된 방향 그래프**로 검증한다.

| 연결 종류             | 허용 조건                                                                                          | 연결하지 않는 경우                                             |
| --------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 같은 구간의 다음 대사 | 같은 조건·장면 내부에서 BWIKI에 연속으로 쓰인 두 대사 모두 매칭되고 사이에 누락/미해석 노드가 없음 | 중간 대사를 못 찾았거나 장면 경계를 건넘                       |
| 선택지 → 응답         | BWIKI의 해당 선택지 본문 안에 응답이 명시되고 두 출현 위치가 매칭됨                                | 번역의 자연스러움·같은 주제·단순 이웃 배열만 맞음              |
| 분기 → 공통 후속      | 위키 구조 또는 공식 실행 그래프에서 같은 합류를 명시함                                             | 서로 다른 응답의 마지막 문장이 비슷하거나 선택지 아이콘만 있음 |
| 조건별/반복 대사      | 각각의 조건과 출현 위치를 유지하고 각 경로에서 별도로 연결함                                       | 같은 원문 ID라는 이유로 서로 다른 분기를 합침                  |
| 장면 → 장면           | 명시적인 실행 연결 또는 확인한 플레이 경로가 있음                                                  | 위키 편집 순서만 있고 장면 전환 의미가 불명확함                |
| 임무 → 임무           | 공식 장 귀속과 위키의 선행/후행 임무 또는 충돌 없는 고유한 시리즈 순번이 맞음                      | 순환·중복 순번·다른 장의 임무·조회 실패                        |

문서 안의 표시 순서는 사이트 본문의 단일 정렬 기준이며 게임 실행 간선과 구분한다. 공식 실행 그래프는 BWIKI 본문을 재정렬하거나 호출 미확인을 이유로 수록을 막지 않는다. 접힌 추가 대화·조건 탭·이미지·장면 설명·미해석 문법은 기본적으로 독립 경계다. 선택지 문구만 확인됐으면 문구는 수록하되 응답 확인 상태를 별도로 남긴다.

미매칭 노드 하나 때문에 구간 전체를 버리지 않는다. 확인한 부분 그래프를 살리되 제거한 노드를 건너는 새 간선을 만들지 않는다. 기존 원문·ID·검증 간선의 손상은 게시를 막는다. BWIKI와 공식 실행 순서의 차이는 내부 비교 기록에 보존하며, 실행 호출의 부재나 서로 다른 출처의 순서 이견을 BWIKI 수록·배치 차단 조건으로 사용하지 않는다.

제8막 A=`146783614`, X=`146783615`, B=`146783616` 사례는 **실행 범위 미확인**이다. BWIKI A→X→B와 특정 Act의 A→B는 인접 연결이 다르지만 상대 선후관계 역전의 증거가 아니다. 실제 충돌이나 오탐으로 확정하지 않는다. 같은 파일의 참조만으로 같은 실행 호출·조건까지 확인한 것으로 취급하지 않는다.

## 일괄 실행·재개·게시

`pnpm verify:trailblaze`는 현재 기준 릴리스를 고정해 모든 등록 장과 공식 `MainMission.ChapterID`의 Main/Gap 임무를 조사한다. 후문처럼 과거 메타데이터에 챕터 ID가 없으면 기존의 명시적 quest 목록과 공식 ChapterID가 유일하게 일치하는 경우에만 복원한다. 연결할 공식 챕터가 없는 연관 모험 임무는 목록에서 사라지지 않고 카탈로그 검토 대상으로 남는다.

기본 실행은 `.cache/source-first/stage`에만 후보를 쓴다. `--offline`은 저장된 수정본만 조사하고 실시간 수정본 확인 성공으로 기록하지 않는다. `--baseline <폴더>`는 별도로 복원한 마지막 배포본을 기준으로 조사한다. `--publish`는 최종 계약·기존 검증 보존을 통과한 단계의 파일만 로컬 게시 데이터로 반영하며 사이트 배포는 필수 테스트·빌드·동일 산출물 검사 후 수행한다.

`catalog.json`, `progress.json`, `results/<키>.json`, `report.json`, `validator-health.json`으로 목록·임무별 결과·중단 지점과 공통 검증기 상태를 보존한다. 체크포인트 키에는 공식 입력 해시/커밋, BWIKI 수정본/실제 바이트 해시, 검증 코드, 정책 버전/해시, 장 기준 데이터, 구조 해시, 번역 검토 기록 해시가 포함된다. 결과 자체 체크섬도 확인한다. 조건이 달라지면 재실행하고 조회 실패는 변경 없음으로 인정하지 않는다.

`public/source-first-provenance.json`은 전체 조사 통계·임무별 상태·출처와 추가 행의 출현 위치·조건·공식 ID·해시를 기록한다. BWIKI 표시 귀속과 공식 실행 귀속은 별도 근거다. 미확정 후보와 전체 그래프는 제외된 체크포인트에 보존한다. 새 원문은 안정적인 ID로 추가하고 기존 행·북마크·검증 간선을 유지한다. BWIKI 출현이 확인된 행에는 해당 표시 위치와 명시된 선택지 응답을 제공한다. BWIKI에 위치가 없는 행만 세부 임무별 `순서 미확인`에 두며, 공식 실행 그래프는 본문 정렬에 사용하지 않는다. 원문 행과 반복 출현 위치는 따로 집계한다.

기존 6시간 Actions 실행은 `workflow-progress.json`, `source-first/progress.json`과 Job Summary에 처리한 장·미처리 범위·보류 사유·재시도 일정을 남긴다. 실패한 실행에서도 체크포인트와 증거 파일을 저장한다. 캐시 소실 시 마지막 성공 배포 스냅샷의 원문·출현·검증 기록과 `verification-progress.json`의 장별 조사 요약/재시도 상태를 복구하며, 분석 결과 캐시가 없으면 필요한 분석을 다시 수행한다. 체크포인트 기록은 게시 성공이나 미확정 후보의 승인으로 취급하지 않는다.

전체 조사 완료는 모든 항목을 처리·보류 상태로 기록했다는 뜻이다. 원문 수록·국소 순서·전체 경로는 서로 다른 상태이며, 전체 경로는 현재 자동 확정하지 않는다. 미지원 문법과 조회 실패는 별도 건수로 함께 보고하며 수록 성공 분모에서 숨기지 않는다.

기존 표준 갱신과 재시도에서도 원문 우선 단계를 실행한다. 이전 소개문 확장기의 전역 일치만으로 신규 행을 만드는 게시 경로는 사용하지 않는다. 기존 정합 대조·시뮬레이션·영상 모듈은 유지한다. 단순 인접 불일치에 대한 기존 정합기의 보수적 보류를 새 실행 충돌 확정으로 재해석하지 않는다.

공통 검증기 예외는 해당 단계의 게시를 중단하고 마지막 배포본을 유지한다. 자료별 미조회·미해석은 해당 문서만 보류한다. `source-first-publication.mjs`가 테스트 전 데이터 목록/해시를 고정하고 빌드 후 공개 데이터의 동일 바이트를 검사한다. Pages에는 이 빌드 아티팩트만 업로드하고 deploy job에서 재수집·재빌드하지 않는다. 기존 게시기의 쓰기 실패 복구와 배포 스냅샷 복원을 회귀 검사한다.

## 변경 후 검사와 재검토

- 수집 목록의 모든 출현 위치가 연결·후보·누락·미지원·조회 실패 중 하나로 추적되는지 검사한다.
- 텍스트 원문·ID·해시·귀속, 출현 위치의 중복, 선택지별 응답 소유, 합류와 순환을 검사한다.
- 기존 검증 그래프를 보존하고, 검색·본문·다국어가 같은 행과 출현 위치를 가리키는지 검사한다.
- 새 위키 수정본·공식 원문 변경·번역 검토 수정 시 관련 후보만 다시 검사한다. 조회 실패는 변경 없음이나 확인 완료로 처리하지 않는다.
- 게시 전에 전체/미연동 수를 **사이트 행 기준과 BWIKI 출현 위치 기준으로 각각** 보고한다. 한쪽의 분모로 다른 쪽의 수록률을 표현하지 않는다.

## 제8막에서 남은 구현 순서

현재 사이트에는 1,576행 중 1,390행이 BWIKI에 연결되어 있고 186행이 미연동이다. 반면 파싱한 BWIKI 대사·선택지는 중복 제거 2,921개 중 1,543개가 미연동이며, 반복 출현 기준으로는 3,114곳 중 1,731곳이다. 장면 설명과 미해석 문법은 별도다.

따라서 다음 작업은 기존 186행의 임계값을 계속 낮추는 것보다 **BWIKI 출현 위치 목록 → 전역 공식 대사 후보 확인 → 누락 원문 추가 → 조건별 출현 그래프 검증** 순서로 진행한다. 전체 공식 데이터에서 같은 중국어·화자를 찾은 미수록 출현 1,368곳을 먼저 조사한다. 중복 ID·타 장면 귀속·종류·한국어 유무를 확인하기 전에는 이 수를 추가 가능한 고유 대사 수로 간주하지 않는다. 세부 수치와 재현 근거는 [재검증 보고서](reports/act8-bwiki-recheck-2026-10-21.md)를 따른다.
