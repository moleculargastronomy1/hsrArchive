# 시뮬레이션 사건 기록

시뮬레이션 우주·곤충 떼 재난·황금과 기계·차분화 우주·인지 불가 영역의 사건을 기존 읽기·검색·다국어 비교와 자동 갱신에 포함한다. 기존 임무 주소와 행 ID는 유지한다.

## 공식 입력과 귀속

- 같은 릴리스의 `RogueHandBookEvent`, `RogueHandBookEventType`, `RogueTournHandBookEvent`로 사건명과 모드 분류를 확인한다. NPC 번호 접두사로 모드를 추정하지 않는다.
- 도감의 명시적 NPC 참조 → `RogueNPC`/`RogueTournNPC`/`RogueMagicNPC`의 파일 경로 → `DialogueList`의 대사·선택지 파일만 사용한다. 잘린 전체 저장소 트리 대신 완전한 Rogue 하위 트리를 조회한다.
- 본문은 명시적 `TalkSentenceID`, 선택지는 `OptionID`→`DisplayID`→`RogueDialogueOptionDisplay.OptionTitle`, 효과는 같은 표시 항목의 `OptionDesc`에 연결한다. 예전 실행 파일의 `OptionTextmapID`가 TextMap에서 해소되지 않아도 숫자를 추정하지 않는다.
- Python 정수로 64비트 해시를 읽고 공식 중국어·한국어·화자 해시를 기록한다. 게임 입력과 위키 원문은 제외된 캐시에만 저장하고 Git blob 및 SHA-256을 검증한다.
- BWIKI 사건명·모드와 공식 도감 귀속을 함께 확인한다. 공통 및 모드 전용 선택지를 분리하고, 모호한 ID·반복 위치·누락 문장·미지원 문법은 검토 기록으로 남긴다. 선택지 효과는 같은 공식 선택지 이름과 설명의 쌍이 정확히 일치해야 한다.
- 명시된 단일 응답만 선택지에 연결한다. 접힌 확률 결과·동적 위키 변수·미지원 조건을 건너뛰어 연결하거나, 관측하지 않은 분기를 완료로 처리하지 않는다.

공식 항목은 `event-rogue-{EventHandbookID}` 또는 `event-tourn-{EventHandbookID}`를 안정적인 장 ID로 사용한다. 본문이 아직 연결되지 않은 항목에도 목차와 대기 안내를 제공한다. 같은 사건이 여러 모드에 속하면 각 모드 아래에 제공하며, 서로 다른 사건·모드의 행을 합치지 않는다. 대조 후보 수는 모드별 수록 완료 수가 아니다.

## 자동 갱신과 재검토

`pnpm update:content`의 원문 투영 다음에 사건 도감과 실행 참조를 준비하고, 기존 BWIKI 발견→수집→대조 다음 단계에서 사건을 연결한다. 검색·비교 언어·최종 계약 검사는 기존 게시 절차를 공유한다. 공식 원문이 갱신되면 사건 원문도 같은 해시로 갱신한다.

GitHub Pages의 기존 **6시간 간격** 예약 실행을 사용한다. 추가 사용자 프롬프트나 별도 Codex 자동화가 필요하지 않다. 성공 조회 후에도 미확인 사건과 선택지 응답은 **24시간 간격** 재대조 대상으로 남는다. 조회 실패는 기존 **6→12→24→48→72시간** 대기와 서버의 `Retry-After` 중 긴 시간을 적용한다. 따라서 제한이 풀린 직후가 아니라 다음 허용된 예약 실행에서 재개한다.

기한이 된 미확인 대상을 우선하며, 마지막 검토·시도 시각으로 순환한다. 독립 재시도는 한 실행에 본문 다운로드와 대조 문서를 각각 최대 20개로 제한하고 나머지를 다음 주기로 남긴다. 수집·대조·이미지 실패와 대기 상태를 저장하며, 조회 실패를 변경 없음으로 확정하지 않는다. 검증 결과가 개선되지 않은 실행은 배포본을 유지한다.

검증 완료 파일은 BWIKI 수집·반영 대상에서 제외하고, 미확인 행·응답이 비어 있는 선택지·신규 사건과 미완료 도감·이미지에 대조 범위를 둔다. 기존 원문·선택지·응답·확인된 순서의 보존 검사는 계속 적용한다. 배포 스냅샷을 복원할 때는 목차가 실제 참조하는 본문만 비교하며, 본문이 아직 없는 새 목차도 보존한다.

이전 연결은 공식 사건 귀속과 원문 해시를 다시 검사한 뒤 보존한다. 새 연결이 기존 원문·선택지·순서·응답·이미지 근거를 없애면 게시를 중단한다. 정상적인 이미지 변경은 새 메타데이터를 검증해 반영하며, 이미지 추가만 있어도 배포한다.

## 사건 이미지

BWIKI 사건 문서의 `images` 목록에 실제 포함된 대표 사건 이미지 중 사건명과 유일하게 대응하는 파일만 `imageinfo`로 확인한다. URL·형식·크기·SHA-1과 파일 설명 페이지를 수집한다. 이미지 바이너리는 저장소에 복제하지 않고 검증한 공개 이미지 주소를 연결한다.

접근 제한 중에는 이미지 요청도 중단한다. 이미지가 없거나 후보가 여러 개면 대기 상태로 유지하며 기존 성공 연결을 삭제하지 않는다. 읽기 화면에 이미지 출처와 HoYoverse 및 해당 권리자의 권리를 표시한다. BWIKI 편집·정리 정보에는 기존 CC BY-NC-SA 4.0 표기를 유지한다.

## 검증 기록

`public/simulation-events-provenance.json`에 공식 입력 해시, 모드별 항목·본문 수, 후보 수, 미확인 사유, 이미지 상태를 기록한다. 이 파일은 마지막 성공 배포의 검증 스냅샷에도 포함한다. 실제 도감의 모든 분기나 게임 전체 진행 검증이 완료되었다는 뜻은 아니다.

필수 검증은 `pnpm test`, Python 단위 테스트, `scripts/validate-content-stage.py`, 사이트 빌드다. 사건 귀속·모드 구분·64비트 해시·선택지 표시 연결·확률 경계·접근 제한·순환 일정·이미지만 추가된 게시와 기존 이미지 보존을 검사한다.
