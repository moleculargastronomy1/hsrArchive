# 한국어 본문 연결과 검증

현재 정책 6은 BWIKI의 표시 순서를 그대로 사용하며 별도의 게임 실행 순서 판정을 하지 않는다. 중국어·한국어 원문과 화자·종류를 대조한다. 여러 공식 ID 후보의 중국어·한국어·화자가 모두 동일하면 원문 저장 레코드를 공유해 BWIKI의 모든 반복 위치에 표시한다. 이때 `rowId`는 텍스트 저장 참조이며 해당 출현의 공식 ID를 하나로 확정했다는 뜻이 아니다. `officialCandidateIds`·`contentCandidates`·`idStatus: unresolved-identical-text`로 후보 전체와 미확정 상태를 유지한다. 후보들의 한국어 내용이나 화자가 다르면 자동으로 합치지 않는다. 번역을 생성하지 않으며 기존 원문·ID·북마크를 보존한다. 내레이션도 같은 기준을 따른다.

질문 및 선택지 묶음의 BWIKI 출현 ID·선택지 개수·각 선택지 위치·앞선 질문 참조를 기록하고, 미연결 질문·부족한 선택지·반복 출현을 보고서의 `choiceCoverage`에서 확인한다. 응답은 BWIKI에 명시된 구조만 사용한다. 기존 실행 검증은 내부 증거로 보존하고, 원문·BWIKI 계층의 참조 해시와 보존 계약만 갱신한다. 새 실행 순서·호출·간선을 생성하거나 이를 본문 수록 조건으로 사용하지 않는다. 수동·6시간 예약·재시도가 기존 공통 경로를 사용하고 정책/코드 해시 변경 시 이전 체크포인트를 재검증한다.

전체 개척·후문의 누락 원문 조사는 `pnpm verify:trailblaze`로 격리 실행하며 표준 갱신에도 같은 단계를 사용한다. 정책 4부터 공식 원문·ID 대응, BWIKI 위치, 공식 실행 관계를 독립적으로 관리한다. 공식 중국어·한국어·화자·종류가 유일하게 대응하고 검증한 BWIKI 임무·장면에 위치가 있으면 실행 호출 없이 안정적인 행 ID로 수록한다. 본문 표시 순서는 BWIKI만 사용하며 공식 실행 자료는 내부 교차검증에 보존한다. BWIKI에 없는 원문은 세부 임무별 `순서 미확인`에 두고 실행 그래프로 본문 사이에 삽입하지 않는다. 기존 행·북마크·연결은 보존한다. 정책과 체크포인트·동일 산출물 배포 조건은 [전체 수록 조건](bwiki-full-coverage.md)을 따른다.

시뮬레이션 우주·곤충 떼 재난·황금과 기계·차분화 우주·인지 불가 영역의 사건 도감, 모드별 본문·선택지와 사건 이미지도 표준 갱신에 포함한다. 공식 참조·자동 재검토·접근 제한 시 보존 기준은 [사건 기록 연동](simulation-events.md)을 따른다.

각 검증 모듈의 역할, 원본/파생 데이터의 경계, 충돌 시 보존 정책과 회귀 검증 명령은 [수집·검증·게시 모듈 구조](verification-pipeline.md)에 정리한다.

## 입력 형식

2026-10-24 기타 분류 누락 조사에서 예약 수집의 HTTP 567 및 NPC 틀의 `对话内容` 필드를 읽지 못하는 오류를 확인했다. NPC는 명시된 대화 필드/절, 메시지는 `短信内容`의 `内容`과 텍스트 대화, 우편은 `邮件`의 `内容`만 정확히 대조한다. 메시지 실제 문서는 `Template:短信内容` 사용 목록과 `短信/` 접두사로 찾는다. 알려진 본문을 목록 조회보다 먼저 처리하고 다섯 분류를 순환 선택한다. 목록 실패 시 호스트 대기를 지키며, 기존의 고정 캐시는 네트워크 없이 재대조할 수 있다. 실패·공식 TextMap 불일치·본문 문법 미지원은 구분해서 기록한다.

개척/시뮬레이션 등의 성공 배포 복구 시 저장소의 검색 후보를 별도 캐시에 보존한다. 검색 전용 변환은 배포 자료와 저장소 후보 양쪽을 공식 KR/CHS 해시·한국어 원문·현재 변환 코드가 같은 경우에만 재사용하여 새 검색 분류가 이전 배포 자료에 덮이지 않게 한다. 소스 코드만 배포할 때는 검색 원격 수집 없이 이 재대조만 허용한다. 본문·화자는 공식 한국어를 유지하고 BWIKI 중국어 제목은 UI 대체 명칭으로 사용하지 않는다.

배포 복구 스냅샷 v3는 파일을 각각 gzip 압축한 뒤 base64로 묶어 다국어 TextMap으로 인한 중간 JSON 용량 증가를 줄인다. 파일의 원래 바이트 해시와 경로를 검증하며, 전체 복원 바이트와 압축 해제 한도를 유지한다. 이전 v1/v2 스냅샷도 그대로 복원한다.

기타 원문의 영어·중국어·일본어 대조는 `scripts/import-search-localizations.py`가 같은 공식 커밋의 KR/EN/CHS/JP TextMap에서 **동일한 정수 해시**만 연결한다. 입력 Git blob·SHA-256과 한국어 검색 입력 일치를 검증하고, 언어별 32개 파일을 `public/search/locales`에 생성한다. 누락된 번역은 생성하거나 유사 문장으로 대체하지 않는다. 로딩 화면 제목은 BWIKI 표의 단순한 제목/본문 한 행 전체를 공식 중국어에 대조하고, 한국어 제목 후보가 모두 같을 때만 연결한다. 본문·제목 ID 후보, 문서 수정 번호와 해시를 언어 manifest에 보존한다. 조건부·복잡한 표나 제목이 다른 후보는 연결하지 않는다. 검색 전용 갱신은 원문·언어 대조를 한 트랜잭션으로 반영하고 같은 검색 커밋만 표시한다.

검색 전용 TextMap 확장(2026-10-23)은 현재 배포 본문과 같은 `74a7b96fba32f00cf495a5c00b0311bd02207aaf` 입력으로 생성했다. 전체 474,189개 문자열 중 기존 원문 검색으로 확인할 수 있는 73,690개와 표시 내용이 비어 있는 9개를 제외한 400,490개를 `public/search`에 추가했다. 기존에 확보한 BWIKI 435개 문서에서 20,962개 추가 원문의 출처를 대조했다. 새 NPC·로딩·상호작용 등의 본문 조회는 HTTP 567 접근 제한으로 중단되어 미확인 상태이며, 미확인 379,528개도 검색에는 포함한다. 전체 분류가 끝났다는 뜻이 아니다.

`scripts/import-search-text.py`는 한국어·중국어 TextMap의 Git blob/SHA-256, 문서의 고정 수정 번호·원문 SHA-256과 변환 코드 해시를 기록한다. Python 정수·문자열 해시로 정확히 연결하며 번역이나 문자열 유사도로 출처를 만들지 않는다. 검색 전용 파생 정보는 `public/search/manifest.json`의 출처 목록·수집 대기와 32개 조각의 `[TextMap ID, 표시 원문, 출처 참조 목록]`에 보존한다. BWIKI 원문·외부 저장소와 이력은 캐시에만 저장한다. 원문 권리는 HoYoverse 및 해당 권리자에게 있고 BWIKI 기반 분류·출처는 CC BY-NC-SA 4.0을 표시한다.

- 입력: 로컬 한국어 자료, 고정 커밋 `a66ec9c36e3321ce4ea9e62b58e9326634628dce`.
- 고정 `dataset/manifest.json`의 조각·전체 압축·파일 SHA-256 검증을 통과한 JSON을 `.cache/starrail-source`로 복원했다. 참고 원본은 수정하지 않았다.
- 지원 입력은 이 스냅샷의 `catalog.json`, 임무 문서 JSON, `starrail-mission-dialogue-supplements.v1`, `starrail-deep-timeline-dialogue.v1`, `starrail-handbook-originals.v1`과 자료실 전용 `hsr-train-databank.v1`이다. 다른 스키마는 오류로 중단한다.

## 변환 규칙과 수록 범위

사용자가 지정한 목차를 정규화한 챕터명과 대조한다. `·`/`•`와 공백 차이를 처리하며, 모험 임무 「내가 쓰는 대로」는 정확한 임무 제목으로 연결한다. 「좋은꿈과 성배」처럼 여러 지역에 걸친 같은 챕터는 해당 임무들을 함께 묶는다.

일반 문서의 `LOCAL_ID_ORDER_MATCH`, 명시적 임무 귀속이 있는 추가 대사, 단일 임무 귀속이 확인된 타임라인 대사를 사용했다. `UNVERIFIED_SCENE_MAPPING` 2,450개 장면은 제외했다. 같은 임무 안에서 같은 대사 ID와 종류의 중복 참조는 한 번 표시한다. 선택지는 별도 표시한다. 사용자 요청에 따라 `{NICKNAME}`과 별표로 감싼 형태를 `[개척자]`로 표시하며, 성별 등 다른 치환 토큰은 유지한다. 지원하는 색상·크기 등 서식 태그는 표시용 문자열에서 제거한다.

시뮬레이션 우주는 실험 임무·곤충 떼 재난·황금과 기계·차분화 우주·기물 기록으로 구성했다. 총 1,333개 읽기 항목(개척 36, 시뮬레이션 291, 아카이브 1,006), 58,598개 표시 행이다. 같은 임무가 분류상 두 곳에서 제공될 수 있으므로 이 수치는 서로 다른 대사 ID의 수가 아니다.

아스트로폴리스 편의 제6막 「천성에 던진 승부수」는 6개 임무의 1,051줄, 개척 후문 「무일푼 재벌 프로젝트」는 9개 임무의 1,120줄을 기존 고정 자료에서 변환했다. 제7막 「달 뜨기 전, 괴수와 춤을」은 최초에는 `MissionChapterConfig` 105009의 한국어 소개문 1줄만 수록했다. 현재는 BWIKI의 해당 시리즈 임무 문서와 공식 대사 ID·자막 TextMap 해시를 연결한 부분 본문을 같은 주소에 추가한다. 소개문은 `DimbreathBot/TurnBasedGameData` 커밋 `312b4597691e0a29cf9828a15b592757dba86949`의 `MissionChapterConfig.json`과 한국어 텍스트 맵 두 파일을 정확한 정수 해시로 연결했다. `scripts/import-astropolis-intro.py`에서 Git blob 해시를 검증하고 SHA-256을 기록한다. 소개문을 대사 본문으로 간주하거나 임무 ID 접두사로 대사를 추정하지 않는다.

각 장의 JSON은 문서 ID, 대사 ID, 원본 구조 경로와 참조 커밋을 남긴다. `docs/content-provenance.json`에 사용한 문서 파일의 SHA-256과 제외 수를 기록했다. `public/content/search-index.json`에는 검색에 필요한 표시 필드와 장면 경계 식별자만 제공한다.

## 화면과 한계

2026-10-23 문맥 보완: 기존 `bwiki-placement.py`가 모든 수동·6시간 예약·재시도 경로에서 BWIKI 출현의 `contextId`를 함께 생성한다. 공식 원문·출현 ID·위치·기존 장면 ID·응답 간선은 유지하며, 파서가 내레이션을 분리한 경우에도 실제 문서에서 연속되고 모두 대응이 확인된 내용은 주변 문맥으로 묶는다. 실제 경계·조건·독립 접힘·선택지 응답·미연결 노드는 넘지 않는다. 이 묶음은 표시 전용이며 공식 실행 간선이나 선택지 응답을 생성하지 않는다. 코드 해시 변경으로 이전 체크포인트를 재검증하고, 조회 불가 시 마지막 검증 위치를 보존한다. 전체 검색은 검색 인덱스의 옛 `review` 상태 대신 장 본문의 출현 위치와 같은 문맥 함수를 사용한다.

에이언즈·고유 명사·파벌은 열차 자료실 전용 `NounAtlas.json`과 `NounAtlasChangeInfo.json`을 한국어 `TextMapKR_0.json`, `TextMapKR_1.json`에 정확한 64비트 해시로 연결한다. 입력 버전은 `DimbreathBot/TurnBasedGameData` 커밋 `724b139d8c9c32d12552eb95745a4fee72bfe48b`이며 Git blob과 SHA-256을 기록한다. Python 정수로 해시를 파싱해 JavaScript 숫자 정밀도 손실을 피한다. 100개 원문이 모두 연결되었고 소개문을 포함해 에이언즈 16개, 고유 명사 40개, 파벌 35개 메뉴로 묶인다.

자료실 메뉴는 소개문을 먼저 표시하고 `SortID`를 따른다. `NounAtlasChangeInfo`의 갱신 관계를 보존하며 같은 항목의 기본 기록과 갱신 기록을 선택할 수 있다. 기본 표시는 가장 뒤의 갱신 기록이며 실제 계정의 스토리 진행·해금 상태를 추정하지 않는다. 시뮬레이션 우주의 에이언즈 연구 기록과 `LoadingDesc` 용어 설명을 자료실 본문으로 사용하지 않는다. 이미지에서 전사했던 「명사」 소개문도 자료실 원문으로 교체했다. 기존 에이언즈·파벌 읽기 주소와 소개문 주소는 별칭으로 연결한다.

나머지 분류는 광추 170개, 적대적 생물 477개, 캐릭터 84개, 유물 184개를 제공한다. 기존 JSON과 같은 참고 커밋의 `public/handbook-originals.json`을 사용하며, 해당 파일은 `editorial/handbook-originals-manifest.json`의 SHA-256과 대조한다. 적대적 생물의 같은 이름을 가진 전투 변형은 한 항목으로 묶고 동일한 문단을 중복 표시하지 않는다. 이 네 분류의 수치는 게임 화면의 도감 개수나 수집 상태와 구분한다.

STORIES 아래 아카이브 메뉴에서 7개 분류로 이동할 수 있다. 분류 안에서는 왼쪽 목록의 이름을 검색하고 오른쪽 패널에서 원문을 읽는다. 홈 배너 오른쪽에 공식 최신 영상을 표시하며, 개척 임무·시뮬레이션 우주·아카이브 메뉴에는 사용자가 제공한 아이콘을 사용한다.

본문은 장별로 불러온다. 전체 검색은 검색 화면에서만 검색 자료를 불러오고 2,000개씩 처리하여 오래된 검색 결과의 반영을 막는다. 결과는 50줄씩 표시한다. 앞뒤 대사는 장·임무·장면·원본 구조 경계를 넘지 않으며 최대 41줄이다. 문자열은 React 텍스트 노드로 표시한다.

자료의 참조 순서는 실제 플레이 순서와 다를 수 있다. 현재 게임 설치 버전을 재추출한 것이 아니며 모든 컷신·분기·변경 대사의 수록을 보장하지 않는다. 연결이 확인되지 않은 장면을 임의로 채우거나 붕괴 3rd 대사로 대체하지 않았다. 실제 본문이 있는 장에서는 예시 대사를 표시하지 않으며, 대사 목록 아래 접힌 영역에 검증 현황과 BWIKI 출처·라이선스를 표시한다.

### 확인된 장면 연결 복원

2026-10-22 공식 실행 보완은 기존 Dimbreath 입력·수집·출판 경로를 확장한다. Dimbreath는 게임 릴리스 데이터의 제3자 보관소이며 HoYoverse의 공식 배포 API로 표기하지 않는다. 원문 권리·기존 Dimbreath 출처 표시는 유지하고, 원본 파일과 외부 Git 이력은 제외된 캐시에만 둔다.

`restore-dialogue-flow.py`의 `execution_slices`는 기존 완전 장면 검증기와 함께 사용한다. 명시된 대화 목록 내부의 순서와 실제 선택지 신호→유일한 대기 대상만 부분 그래프로 기록한다. 같은 ID의 반복은 JSON 포인터별 출현으로 구분한다. 동시 시작 시퀀스·초기화/시작 단계·조건 가지를 합치지 않는다. 미제공 타임라인, 영상, 미지원 작업, 빠진 레코드와 반복 간선을 건너 연결하지 않는다. 비활성 부모의 자식 작업과 의미를 해석하지 못한 중첩 컨테이너는 잠정 후보다. 비동기 단일 대화 작업 사이에는 명시된 완료 대기가 필요하다.

`source-first.mjs`의 기존 수집기가 같은 고정 커밋의 Performance A/C/D/DS/CG/E 표와 `PerformanceSubMissionLink`를 추가로 검증한다. `execution-placement.py`는 MissionInfo의 시작 세부 임무, `AnySequence`/`AllSequence` 선행 참조, `MissionJsonPath`, Performance ID→실제 경로 및 대상 실행 타입을 대조한다. 숫자 접두사·파일명 유사도로 호출을 만들지 않는다. 임무 선행 조건은 임무 의존성이며 대사 사이의 실행 간선으로 바꾸지 않는다. 호출 파일·조건·표의 Git blob/SHA-256을 근거에 남긴다.

한국어 원문 수록에는 같은 커밋의 공식 중국어·한국어·화자·종류와 BWIKI 출현의 유일한 대응을 사용한다. 공식 실행 파일의 호출은 수록 필수 조건이 아니다. 새 BWIKI 수록 행의 `missionEvidence: bwiki`와 문서 그룹 ID는 표시 귀속이며 실제 공식 임무 호출을 주장하지 않는다. 기존 공식 원문·ID·원래 귀속·검증 간선은 바꾸지 않는다. 원문이 같은 반복 출현은 행을 공유하고 출현 ID를 나눈다. 추가 원문은 기존 안정 ID 규칙을 따르며 검색·다국어 투영에 함께 반영한다.

본문의 선택적 `executionReading`은 공식 파일 내 정적 출현, 조건, 로컬 간선과 호출 증거를 내부 교차검증 자료로 담는다. 본문은 `wikiReading`의 BWIKI 표시 순서만 사용하며 실행 자료로 대사를 삽입하거나 재정렬하지 않는다. 이전 실행 기반 표시 배치는 `legacyDisplayPlacements`에 보존하고, BWIKI 위치가 없는 원문은 세부 임무별 `순서 미확인`에 둔다. 서로 다른 실행 범위의 제8막 사례는 계속 실행 범위 미확인이다.

정기 경로는 BWIKI 대조→조회 대기 문서의 고정 출현 복구→공식 실행 교차검증 순으로 처리한다. 실행 투영은 복구가 끝난 BWIKI 계층의 해시를 참조한다. 원문·조건·반복·간선·표시 배치 손실은 공통 보존 검사로 차단한다. 검증 코드·정책 4·공식 입력·실행 표 해시는 재검증 키에 포함하며 JavaScript 정수 범위를 넘는 조건 해시는 문자열로 보존한다. 잠정 관계·귀속 불일치·미수록 원문 후보·순서 이견의 전체 기록은 격리 `execution-results`에 남긴다. 일반 목록에 기술 문구를 추가하지 않는다.

같은 공식 버전의 BWIKI 재시도 후보가 기존 장의 근거와 충돌하면 마지막 정상 장을 유지한다. 그 장에 등록된 신규 원문도 함께 추가됐다면 새 행·검색·목차 개수·수록 근거를 함께 격리하며 다른 장의 확인된 수록을 막지 않는다. 새 행을 임의로 기존 연결에 합치거나 새 번역 대응을 승인하지 않는다. 등록되지 않은 수록 방식과 공식 원문/실행 손상은 계속 전체 반영을 중단한다.

기존 검증 배포본에 공식 실행 보완만 격리 적용할 때는 `pnpm verify:trailblaze --execution-only`를 사용한다. 기존 BWIKI 수집·재매칭을 반복하지 않는다. `--offline --replay`는 동일 커밋의 계획과 구조 체크포인트가 이미 있을 때만 가능하며, 최종 원문·검색·다국어·복구 계약은 계속 검사한다. 전체 비교와 범위 제한은 [실행 보완 보고서](reports/dimbreath-execution-2026-10-22.md)를 따른다.

`scripts/dialogue-flow.mjs`가 현재 적용한 동일 릴리스 커밋에서 기존 임무 행이 명시적으로 참조하는 `Config/Level/Mission`, `Story/Mission`, `Story/Discussion/Mission`의 JSON만 조회한다. Git tree가 잘렸으면 게시를 중단하고, 모든 입력 Git blob을 검증한다. 원본은 제외된 `.cache/upstream-content/blobs`에만 저장한다.

`scripts/restore-dialogue-flow.py`는 지원하는 직접 대화 목록과 실제 `TriggerCustomString` → `WaitCustomString` 연결을 맞춘다. 마커의 숫자나 대사 ID의 크기, 파일명·문장 유사도로 연결하지 않는다. 시작점이 하나이고 모든 분기가 연결되는 비순환 장면만 사용한다. 완전히 수록된 장면은 해당 장면의 기존 행 위치 안에서만 순서를 복원하며, 공통 후속 대사는 모든 선행 분기 뒤에 배치한다. 여러 선택의 응답은 화면에서 각각 어떤 선택지의 응답인지 표시한다. 장면 사이의 실제 플레이 순서는 아직 검증한 것으로 간주하지 않는다.

타임라인·조건부 실행·반복·충돌은 기존 순서를 유지하고 `flowStatus: review`로 남긴다. 구조는 명확하나 수록 대사가 부족한 장면은 기존 행의 명시적 연결만 제공하며 재정렬하지 않는다. 누락 경계는 `flowBoundary`와 누락 대사 ID로 기록하고, 이후 문장을 추정하거나 임의로 채우지 않는다. 모든 기존 대사 ID·본문·화자·종류와 행 개수를 보존하며, `referenceOrder`로 원래 배열을 보관해 다음 갱신에서 연결 근거가 사라지면 복원 전 순서로 되돌린다.

확인된 선택지를 누르면 해당 응답과 공통 후속 대사만 최대 41줄 표시하고 다음 선택지나 미확인 경계에서 멈춘다. 원문 검색과 다국어 비교는 같은 행 ID를 사용한다. 검증한 입력의 Git blob·SHA-256, 복원 수와 확인 대상·사유는 `public/dialogue-flow-provenance.json`에 기록한다. 이상 낙원 제3막 28페이지의 `quest-1054212` 타임라인 구간은 실행 원문이 없어 확인 대상으로 유지한다.

## 재생성

### BWIKI 순서·분기 대조

표준 `pnpm update:content`는 텍스트 갱신과 원본 실행 구조 복원 후 항상 BWIKI 대조를 실행하고, 그 결과로 전체 검색과 다국어 비교 파일을 게시한다. `bwiki-dialogue.py --discover`가 같은 릴리스의 `MainMission.Name`을 정확한 정수 해시로 중국어 제목에 연결한다. 중복 제목은 추정하지 않는다. `fetch-bwiki.mjs`는 공개 API에서 제목·명시적 리다이렉트·문서 수정 번호·시각·원문을 받는다. 요청은 20문서씩 순차 처리하고 1초 간격을 둔다. API 이어받기를 처리하며 접근 제한·429·보호 HTML을 받으면 추가 요청을 중단한다. 원본 문서는 제외된 캐시에만 저장한다.

대사 구역의 `剧情选项`에서 `选项N`과 `剧情N`을 각각 선택지와 응답으로 읽고 중첩 분기를 보존한다. 색상·주음·링크 등 지원하는 표시 문법만 해제한다. 공식 중국어 대사를 임무 안에서 화자·종류와 함께 유일하게 대조하고, 정확한 `TalkSentenceID`의 한국어가 기존 표시 원문과 일치할 때만 연결한다. 대조용 문자열은 루비의 본문만 사용하고 주인공 기본 이름 `开拓者`의 치환·대괄호 차이, 서식·공백·유니코드 문자 폭과 문장부호 차이를 정규화한다. 단어·숫자·숫자 사이의 소수점·쉼표·미해결 치환 토큰과 화자 표기는 유지한다. 게임 원문의 중국어·화자·한국어 전체 해시는 이전 기준으로 유지해 루비 주석이나 실제 원문이 바뀌면 이전 연결을 재검토한다. 시뮬레이션 문서의 `事件|화자|본문`과 `事件|星神|화자|본문`도 명시된 화자의 대사로 읽고 선택지·응답 구조를 보존한다. 미지원 사건 형식은 경계로 남긴다. 번역·문장 유사도·숫자 접두사로 귀속을 만들지 않는다. 이름이 같은 여러 임무, 반복 문장·반복 위키 위치, 누락·미지원 문법과 원본 실행 연결 충돌은 건너뛰며 경계를 넘겨 연결하지 않는다. 접힌 추가 대화·장면 지시·이미지는 별도 경계다. 선택지의 ‘대화’·‘종료’ 아이콘만으로 되돌아가기나 공통 후속 실행을 추정하지 않는다.

2026-10-21부터 기존 원문 정확 일치에 **명시적으로 기록한 번역 내용 대조**를 보조한다. `editorial/bwiki-translation-matches.json`에서 BWIKI 중국어 발화를 한국어로 번역한 내용과 이미 수록된 공식 한국어 문장의 행동·대상·부정·숫자·고유명사를 비교한 근거를 관리한다. 주변 이야기의 맥락만 맞거나 자동 문장 유사도 점수만 높은 경우는 채택하지 않는다. 공식 ID·한국어 원문·종류·화자와 같은 장의 유일성은 유지하고, 위키 고정 수정 번호·전체 문서 해시 및 공식 중국어·한국어·화자 해시가 모두 맞을 때만 검토한 표기 차이를 허용한다. 새 위키 수정본은 자동 의미 추정하지 않으며, 이전 근거의 재사용도 같은 기록과 해시를 확인한다. 기존의 번역으로 임무 귀속을 만들지 않는 규칙은 유지한다.

번역 내용으로 연결한 행에는 `bwikiMatchMethod: translation-reviewed`와 화면의 `번역 내용 대조` 표시를 남긴다. 감사 기록에는 번역문·판단 근거·검토 기록 해시를 보존한다. 반복 위치·불명확한 선택지 때문에 고유 대사까지 함께 버리지 않고, 모호한 행만 제거한 독립 부분 그래프로 보존한다. 응답을 확인하지 못한 선택지 문구는 연결 없이 독립 수록하며, 내레이션은 공식 내레이션 원문과 유일하게 일치할 때만 별도 구간으로 연결한다. 제거한 위치·장면 경계를 건너는 간선을 새로 만들지 않는다. `span` 표시 태그와 `{{=}}` 표시 문법도 해제한다.

특정 장만 다시 대조하려면 `pnpm update:content --retry --title "제8막: 어제의 내일이 되어"`를 사용한다. 같은 공식 입력 버전에서 장 제목 하나를 정확히 선택하며, 관련 BWIKI 문서만 조회하고 다른 장·영상·사건의 대조를 강제하지 않는다. 부분 실행은 전체 BWIKI 알고리즘의 처리 완료 상태를 갱신하지 않는다. GitHub Actions 수동 실행의 `trailblaze_title`도 같은 경로를 사용한다.

중국어 원본을 별도 보관하려면 `python scripts/save-bwiki-reference.py <검증한-manifest.json> .local/bwiki/<참조폴더>`를 사용한다. 해시를 검증한 위키 원본·구조화 JSON·읽기용 중국어 Markdown·수정 번호와 출처·라이선스를 함께 저장한다. `.local/bwiki/`는 Git 제외 경로이며 자동 갱신 캐시와 분리한다. 제4장 제8막의 결과와 한계는 [재검증 보고서](reports/act8-bwiki-recheck-2026-10-21.md)에 기록한다.

기존 임무 묶음에 일치 대사가 없을 때는 같은 장 전체에서 중국어 본문·화자·종류가 유일하게 일치하는 기존 행까지 연결한다. 원래 `missionId`·임무명·출처는 바꾸지 않고 BWIKI의 임무 귀속을 `bwikiMissionId`·`bwikiMission`으로 별도 기록하며 표시·응답 탐색에 사용한다. 다른 장의 행을 가져오거나 누락 대사를 생성하지 않는다. BWIKI의 명시된 선행·후행 임무 링크와 같은 임무 시리즈의 고유한 순번으로 장 내부 임무 선후 관계를 정리하고, 순환·충돌이면 기존 임무 순서를 유지한다.

일치한 전체 행의 기존 위치 안에서 확인한 임무 순서와 BWIKI 편집 순서대로 정리하고, 미확인 행 위치·전체 대사 수·ID·본문·화자·종류·출처를 보존한다. `bwikiBaseOrder`는 BWIKI 적용 직전 배열이며, `referenceOrder`는 최초 자료 배열이다. BWIKI 연결은 원본 실행 연결과 다른 필드에 저장한다. 대사마다 완료 표시는 붙이지 않고 세 근거(원본 구조·BWIKI·자막) 모두 없는 검토 대상에만 `(순서 미확인)`을 표시한다. 실제 플레이 녹화로 전체 순서를 검증한 상태로 간주하지 않는다.

`public/bwiki-provenance.json`은 게임 입력 커밋·Git blob·SHA-256, 위키 문서별 수정 번호·시각·SHA-256·기여 이력 링크, 적용한 ID·분기와 미확인 사유를 기록한다. 이 공개 파생 기록을 이전 입력으로 사용할 수 있다. 위키 조회 실패 시 이전 연결의 모든 공식 중국어·한국어·화자 해시, 대사 ID와 임무 내 유일성을 재검증하고 원본 실행 연결과 충돌하지 않는 경우만 `cached`로 유지한다. 하나라도 달라지면 해당 대조 구간은 적용하지 않는다. 새 조회와 이전 대조 유지 상태를 화면에 구분해 표시한다.

BWIKI 편집·정리 정보는 [BWIKI 기여자](https://wiki.biligame.com/sr/开拓任务)의 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/)에 따라 한국어 자료의 대사 ID와 연결한 파생 정보로 제공한다. 페이지의 고정 수정 버전과 이력을 출처로 남기며 수정 사실을 표시한다. 이 표기는 BWIKI 기반 정리 정보에 적용하며 사이트 코드와 HoYoverse 게임 원문의 권리와 구분한다. 위키 템플릿·JavaScript 코드를 재사용하지 않았다.

수동으로 최초 변환기를 실행하거나 텍스트 파일을 바꾼 경우 게시 전에 `pnpm update:content`를 실행해 BWIKI 대조·검색·다국어 기록을 다시 맞춘다.

기록된 커밋의 복원된 자료를 `.cache/starrail-source`에 준비한다. 부가 입력의 `public/handbook-originals.json`과 `editorial/handbook-originals-manifest.json`은 `.cache/starrail-input` 아래에 같은 상대 경로로 준비한다. 부가 입력 폴더는 변환 명령의 두 번째 인수로도 지정할 수 있다. Python·Node 실행 파일은 설치 환경에 맞게 선택한다.

```powershell
node scripts/fetch-train-databank.mjs
python scripts/import-train-databank.py
python scripts/import-astropolis-intro.py .cache/astro-source
node --experimental-strip-types scripts/import-local-dialogue.mjs .cache/starrail-source .cache/starrail-input
pnpm test
pnpm build
```

원본 코드·전체 복원물·Git 이력은 커밋하지 않는다. 사이트에 필요한 변환 결과만 포함한다. 게임 원문과 이미지의 권리는 해당 권리자에게 있다.

## 릴리스 원문 자동 갱신

최초 고정 자료의 임무·장면 연결을 유지하면서 최신 한국어 문자열을 반영하는 [자동 갱신](automatic-content-updates.md)을 배포 작업에 연결했다. 이 문서의 고정 입력·초기 변환 기록과 자동 갱신의 적용 버전은 구분한다. `public/content-update.json`에서 현재 적용한 커밋과 수록 범위를 확인할 수 있다.

신규 개척 임무는 `scripts/import-trailblaze.py`가 한국어 제목과 공식 챕터 ID, `MainMission.ChapterID`, 정확한 임무 디렉터리의 명시적 대사 참조로 연결한다. 숫자 접두사나 문장 유사도로 귀속을 만들지 않는다. 제7막의 실행 구조는 아직 없으며, BWIKI 대조로 부분 본문을 수록한다. 새 입력의 해시·수록 상태·누락 사유는 `public/trailblaze-provenance.json`에 기록한다. 지원 스키마와 제목 검색 실행 방법은 위 자동 갱신 문서를 따른다.

## 다국어 비교 원문

한국어에 적용한 동일한 릴리스 커밋의 `TextMapEN`, `TextMapCHS`, `TextMapJP`를 사용한다. 현재 고정 커밋은 `312b4597691e0a29cf9828a15b592757dba86949`이며 입력 Git blob·SHA-256과 언어별 수록 수는 `public/content/locales/manifest.json`에 기록한다. 각 언어에서 58,274줄(선택지 4,271줄)을 연결했고 324줄은 연결 근거가 없어 미제공으로 남긴다.

`scripts/import-localizations.py`는 Python 정수로 해시를 읽어 `TalkSentenceConfig`의 대사 ID, 보존한 `text-bindings.json`, `NounAtlas`의 정확한 기록 ID와 `MissionChapterConfig` 소개문을 연결한다. 같은 해시의 한국어가 실제 표시 원문과 일치할 때만 외국어를 제공한다. 순서나 유사한 문구로 추정하지 않는다. 자료실의 기본·갱신 기록은 각각의 행 ID로 보존한다. `{NICKNAME}`은 언어별 개척자 표기로 치환하며 다른 치환 토큰은 유지한다.

자동 갱신이 네 언어를 함께 검증·변환한다. 로컬에서 이미 검증한 다국어 계획과 원본을 준비한 경우 다음처럼 비교 파일만 재생성할 수 있다.

```powershell
python scripts/import-localizations.py . .cache/upstream-content/raw .cache/upstream-content/plan.json
```

원본 파일 전체는 캐시에만 보관하고 사이트에 수록한 행의 변환 결과만 제공한다. [DimbreathBot/TurnBasedGameData](https://github.com/DimbreathBot/TurnBasedGameData)의 안내에서 데이터 사용 시 출처 표시 요청을 확인했다. 외부 코드는 재사용하지 않았다. 게임 원문의 권리·저작권은 HoYoverse 및 해당 권리자에게 있다.

## 공식 영상

한국어 공식 채널 `UCH33CJMcI0XZUpIhWRHiUuw`의 공개 Atom 피드를 사용한다. 사용자가 지정한 `/videos` 화면에 맞춰 일반 영상 중 최신 항목을 선택하며, 일반 영상이 없는 피드에서만 Shorts를 사용한다. 6시간마다 및 소스 배포 시 확인하고, 장애 시 마지막 검증본을 유지한다. 썸네일을 누르면 공식 YouTube 임베드를 재생하며 원본 채널 링크도 제공한다. 별도의 API 키를 사용하지 않는다.

### 소개문에서 BWIKI 본문으로 확장

`import-bwiki-chapters.py --discover`는 소개문만 있는 장과 `bwikiManaged` 장을 확인한다. 검증한 `MissionChapterConfig`의 챕터명과 `MainMission.ChapterID`·공식 중국어 임무명으로 문서를 조회하며 신규 장을 우선 요청한다. BWIKI의 임무 유형·명칭·시리즈가 같은 공식 챕터와 일치해야 본문을 연결한다. 이름이 같은 여러 세부 임무는 공식 ID 목록을 유지한 문서 단위 `bwiki-page-{문서 ID}`로 기록하고 어느 세부 임무인지 추정하지 않는다.

공식 중국어 본문·화자와 같은 표시 문자열이 `TalkSentenceConfig` 전체에서 유일하고 한국어 원문이 있을 때만 행을 추가한다. BWIKI의 일반 장면 역할은 공식 화자가 유일한 경우만 연결한다. 명시된 `字幕`는 대사 ID가 없더라도 동일한 중국어 표시 문자열의 TextMap 해시가 유일하고 같은 해시의 한국어가 있을 때 원문 자막으로 추가한다. 이 구분과 전체 중국어·화자·한국어 검증 해시를 공개 감사 기록에 남긴다. 새 행 ID는 챕터와 공식 ID·종류를 기반으로 고정하며 기존 소개문 ID를 보존한다.

선택지 ID가 불명확하거나 조건 설명으로 작성된 위키 선택지는 게임 선택지로 만들지 않는다. 그 안의 확정 가능한 대사는 독립 구간으로 수록한다. 탭으로 구분된 조건별 대화도 각각 독립 구간이며 경계를 건너 응답 연결을 만들지 않는다. 반복 위키 위치·중복 ID·누락·미지원 형식은 검토 기록을 남긴다. 조회 실패 시 이전 전체 원문 해시와 전역 ID 유일성을 다시 검증한 연결만 유지하고, 기존 행은 삭제하지 않는다. `bwiki-provenance.json`의 `imports`와 `trailblaze-provenance.json`의 `bwiki-partial`/`rawStatus`로 실행 구조 미제공과 BWIKI 부분 본문 수록을 구분한다.

### 한국어 플레이 영상 보조 대조

BWIKI 이후 `verify-video-order.mjs`가 사용자 지정 K tube 스토리 재생목록을 한국어 표시 언어로 갱신한다. 공개 재생목록의 이어받기 데이터를 읽되 접근 제한은 우회하지 않는다. `video-chapter-links.mjs`는 공식 챕터 제목 또는 같은 공식 챕터 ID에 속한 한국어 임무 제목과 영상의 인용된 제목을 정확히 대조한다. 지역의 장 번호·임무 유형을 함께 확인하며 이벤트/동행 영상은 제외한다. 영상 `#번호`를 막 번호로 바꾸지 않는다. 분할 후문처럼 여러 장에 해당하거나 제목 변경·번역 때문에 연결이 모호하면 검토 기록만 남긴다. `missionCatalog`는 같은 공식 입력으로 생성하고, 이전 연결 임무명도 BWIKI에서 확인된 것만 보조한다. 최신 장 우선·오래된 확인 순으로 실행당 최대 두 영상의 공개 한국어 자막을 조회한다. 동영상 파일은 다운로드하지 않으며 로그인·편집 권한이나 보호 토큰을 우회하지 않는다.

자막은 공식 한국어 원문의 표기만 정규화해 16자 이상인 고유 문장을 정확하게 대조한다. 음성 인식 자막의 유사 문장·멀리 떨어진 자막 조합·짧거나 반복되는 문장·음성에 없는 선택지는 근거로 쓰지 않는다. 같은 장에서 세 문장 이상을 찾고, 같은 BWIKI 임무의 앞뒤 앵커 사이에서 관측된 미확인 대사만 순서에 반영한다. BWIKI 앵커의 선후 관계와 원본 실행 연결이 확인된 대사는 덮어쓰지 않는다. 이는 그 플레이 경로에서의 자막 대조이며 모든 분기나 전체 실제 플레이 검증을 뜻하지 않는다.

`video-order-provenance.json`에 영상 목록·제목 연결 방법/공식 제목·연결 실패 후보·미확인 행·대조 시각·자막 종류/해시·시각별 행 ID·충돌/실패 상태를 남긴다. 이전 자막 증거도 현재 한국어 해시와 유일성을 재검증하며, 읽을 수 없는 자막이나 모호한 결과는 검토 대기다. 원본 자막·서명된 자막 URL·토큰은 게시하지 않는다. 가벼운 `video-review-summary.json`을 하단 접힌 안내에서 읽어 해당 장의 한국어 영상과 대조 상태만 보여 준다.

시뮬레이션 우주는 검토한 모드·사건·대상 파일을 `video-verification-sources.json`에 명시한 영상만 연결한다. 공개 자막 내보내기로 확보한 정확한 대사와 직접 확인한 화면 경로는 `editorial/video-observations.json`에 파생 증거로 보존한다. 화면 경로는 같은 공식 출처·임무의 ID·원문 해시·선택지 역할과 연속 관측을 검사하고, 별도 영상 간선에만 반영한다. 화면에서 확인하지 못한 선택지·다른 사건·다른 플레이 경로는 합치지 않는다. 원문 입력과 BWIKI 수집·매칭 모듈은 그대로 유지한다. 데이터 계약과 독립 재시도 방식은 [검증 모듈 구조](verification-pipeline.md#2026-10-18-영상-근거와-독립-재시도-보완)를 따른다.

### BWIKI 출현 위치 복원

`source-first.py`는 전체 개척 임무 감사 후 `bwiki-placement.py`로 기존 공식 원문 행의 출현 위치를 만든다. `hsr-wiki-reading.v1`은 고정 문서 수정 번호·해시, 세부 임무 묶음, 장면·조건·선택지 가지, 원문 행 ID 참조, 표시용 출현 간선과 미확인 목록을 담는다. 문서의 표시 순서만 확인하며 `nextIds`라는 이름의 출현 간선도 공식 실행 간선으로 승격하지 않는다.

같은 공식 커밋의 중국어·화자·한국어를 재검증하고 기존 임무 범위·명시된 공식 참조를 검사한다. 수록되지 않은 공식 ID도 중복 후보 검사에 포함한다. 반복 문자열의 구분에는 양쪽의 고유 앵커와 같은 공식 파일·배열·조건 범위가 모두 필요하다. 새 번역 의미 대응이나 불확실한 임무 귀속은 확정하지 않는다. 선택지의 비어 있는 응답은 공통 후속 대사로 채우지 않으며 미확인 노드·조건·장면 경계를 건너 연결하지 않는다. 이미 검토한 번역은 해당 수정본과 검토 기록이 유효한 경우에만 유지한다.

공식 원문 `rows`는 원래 순서·ID·화자·원문·귀속·기존 간선까지 보존한다. 위치 미복원 행 중 기존 검증 근거가 있는 행은 원래 연결을 유지해 별도 표시하며, 나머지는 원래 세부 임무별 `순서 미확인`으로 관리한다. 전체 후보와 실패 이유는 격리 체크포인트에 남긴다. 사용자 TXT는 이 생성 과정에 사용하지 않는다. 제8막 A→B / A→X→B는 계속 실행 범위 미확인이다.

최종 계약 검사는 원문 체크섬, 출현 ID·참조·전체 행의 배타적 분할, 문서 고정 해시, 장면·조건·분기 경계와 순환을 검사한다. 복구 기준 선택과 변경 탐지는 새 출현 계층도 포함해 원문 행이 같다는 이유로 배치 정보를 잃지 않게 한다. 기존 출현 수·연결이나 같은 출현 ID의 의미가 손상되면 자동 반영을 중단한다. 배포에는 최종 검사한 동일 산출물을 사용한다.

### 실제 배포 연동 감사

`wiki-reading-recovery.mjs`는 예약 수집에서 명시적으로 조회 대기·실패한 문서만 이전 고정 출현과 간선을 보존한다. 같은 공식 커밋·기존 원문이 그대로여야 하며, 이전 검증 코드·정책·입력 버전과 문서 수정본을 `retainedSources`에 별도로 남긴다. 현재 문서를 새로 검증한 것으로 처리하지 않는다. 실제 확보한 문서에서 위치·간선이 줄거나 원문이 바뀌면 보존 예외로 덮지 않고 공통 손실 검사가 자동 반영을 중단한다.

`pnpm export:bwiki-comparison -- --work .cache/wiki-placement/full --output .cache/wiki-placement/exports`는 완료한 격리 감사와 현재 원문·출현 계층을 읽어 36개 TXT와 제8막 별도 파일을 만든다. 파일 A는 BWIKI 출현 순서, B는 실제 렌더러의 사이트 순서, C는 경계·미지원 구조, D는 수정본·보류 사유다. 고유 원문 행 대신 개별 출현 ID를 사용해 반복과 분기를 보존한다. 중국어 표시 본문·화자·공식 한국어 원본·사이트 한국어·공식 ID·두 순번·일치 여부·보류 사유를 기록한다. 특수 공백·서식·이름 토큰은 기존 공식 표시 변환으로 검사하며 원본도 별도 열에 남긴다. 새 번역 연결은 하지 않는다. 원문 조회가 불가능한 기존 자리표시 행은 원문 누락으로 구분한다. 원문을 포함하는 결과물은 `.cache`에만 저장하고 Git에 커밋하지 않는다.

`scripts/audit-integrations.py`는 실제 사이트의 36개 장과 BWIKI·영상 공개 기록을 내려받고 같은 커밋의 공식 중국어/한국어·TalkSentenceConfig를 정수 해시로 다시 검증한다. 대사 근거·수정 번호·간선과 실제 게시 행의 일치, 수집본 SHA-256, 수집 시각(문서 수정 시각과 별개), 자막 성공/실패/미조회, 미확인 원인과 기존 원문 보존을 장별로 보고한다. 문서·영상 제목 연결이나 Actions 성공을 전체 완료로 간주하지 않는다. 전체 플레이와 모든 분기의 독립 검증 범위를 입증하지 못하면 최대 부분 완료다.

```sh
python scripts/audit-integrations.py --output docs/reports/integration-audit-2026-10-17.md
```

한국어 Markdown과 기계 판독용 JSON을 함께 생성한다. 공개 사이트의 입력 커밋이 로컬 검증 원본과 다르거나 감사 중 배포가 바뀌면 중단한다. `--local`은 배포 전 데이터 자체를 점검하는 모드로, 사이트 반영 성공으로 집계하지 않는다. BWIKI의 `终末任务`도 지원한다. 같은 중국어 제목의 세부 임무는 공식 챕터 ID·한국어 제목이 모두 같은 경우에만 실제 문서 ID 단위로 묶으며 원래 행의 임무 귀속을 바꾸지 않는다.
